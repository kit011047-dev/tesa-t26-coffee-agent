# แผนปรับราคา agent — ตลาดแข่ง 20 พ.ย. (ด่าน 3)

เขียนจากโค้ดและ log ที่มี (sandbox 26 เกม) ไม่ใช่จากตลาดแข่งจริง · ค่าที่ไม่แน่ใจมีเครื่องหมาย ❓ ให้ตรวจตอนซ้อม

## หลักคิด
- ผู้ซื้อรับซองราคาต่ำสุดก่อน และ **ราคาที่เสนอคือราคาที่ได้จริง** → ขึ้นราคาเมื่อขายได้ง่าย ลดเมื่อแพ้
- ของที่ขายไม่ได้ได้แค่ **0.80 × TV** → ขายที่ต่ำกว่า 0.80 แย่กว่าเก็บไว้ พื้นของเรา `MIN_MARKUP = 0.85` ปลอดภัย **ไม่แตะ**
- คะแนน PR วัดเทียบทีมที่ PR สูงสุด → ถ้าราคาที่ชนะสูงกว่าที่เราเสนอ เราเสียคะแนนโดยไม่รู้ตัว
- แก้โค้ด/ค่าตั้งแล้วรีสตาร์ท agent ได้ตลอด (สไลด์หน้า 7) แต่ **รอบที่พลาดไม่ได้คืน** → แก้ในช่วงซ้อมเท่านั้น

## ช่วงซ้อม P1–P2: เก็บข้อมูลแล้วจูนค่าเริ่มต้น
สิ่งที่อยากรู้: ตัวคูณ (ราคา ÷ TV) ที่ขายได้ของแต่ละประเภทผู้ซื้อในตลาดจริง

1. หลัง P1 (≈10:01) ดู `logs/decisions.jsonl` และ dashboard: ต่อประเภทผู้ซื้อ สัดส่วน ขายได้ / OUTBID / ABOVE_LIMIT และตัวคูณสูงสุดที่ขายได้
2. ปรับ `START` ใน [strategy.py](../strategy.py) ตามตาราง แล้วรีสตาร์ทก่อน P2 จบ (ต้องเสร็จก่อน 10:07)

| เห็นใน P1 | ปรับ `START` ของประเภทนั้น |
|---|---|
| ขายได้ ≥ 85% ของซอง และขายที่ราคาบนสุดของขั้นบันได | **+0.02** (ทิ้งเงินอยู่) |
| OUTBID > 40% | **−0.02** |
| ABOVE_LIMIT > 10% | **−0.03** (เกินเพดานลับ) |
| อื่น ๆ | ไม่แตะ |

3. ค่าเริ่มต้นปัจจุบัน: Specialty 1.05 · Commercial 1.00 · Instant 0.92 (ตั้งจาก sandbox — ตลาดจริงอาจต่าง)
4. ❓ ตรวจว่า agent เรียนรู้จากรอบซ้อมต่อเข้ารอบจริง: ที่ R1 ดูบรรทัด `learned: ...` ใน log ว่ามีค่าของผู้ซื้อที่เจอในซ้อมหรือไม่ ถ้าไม่ ให้ใช้ข้อ 2 แทน

## รอบจริง R1–R5 (ปกติ)
- agent ใช้ขั้นบันไดเดิม: ขายได้ +0.01 · OUTBID −0.01 (ติดกันสูงสุด −0.03) · ABOVE_LIMIT −0.03
- **ไม่ปรับมือ** ยกเว้นตัวชี้วัดข้างล่างชนเงื่อนไข

## เทศกาล R6–R8 (Specialty ต้องการมาก)
- สิ่งที่ agent ทำอยู่แล้ว: ล็อตเกรด Specialty ได้ส่วนแบ่งขายมากขึ้นในช่วงนี้ (ล็อตอื่นไม่เปลี่ยน)
- ใหม่ (ทำก่อนเริ่ม ถ้ามีเวลา): ที่ R6 ถ้า RFQ Specialty มีจำนวนกระสอบรวมมากกว่า R5 อย่างน้อย 30% ให้ Specialty markup **+0.03** ครั้งเดียว แล้วให้ขั้นบันไดตามปกติ · ถ้าไม่เพิ่ม ไม่ต้องทำอะไร
- ตรวจ `specialty_share` ที่ตลาดบอก ❓ ถ้าสูง = ตลาดดัน Specialty จริง

## R9–R12 (ปกติ) และ R13–R15 (ลดลง → ต่ำสุด)
- **ไม่ต้องปรับ `ENDGAME` และ `PACE`** — ทดสอบใน `tools/sim_day3.py` (15 รอบ + ปฏิทิน + capacity, 80 เกมต่อชุด, ทั้งโหมดปกติและโหมด Specialty):
  - `ENDGAME` 5 แบบ (ไม่ลดเลย / 3 รอบ อ่อน-แรง / 4 รอบ) และ `PACE` 1.3 / 1.9 / 2.2 ต่างจากค่าเดิมไม่เกิน 0.0015 PR (อยู่ในความแกว่งของการสุ่ม)
  - ข้อเดียวที่เห็นชัด: `PACE 1.3` แย่กว่าเล็กน้อย → **ไม่ลด PACE ต่ำกว่า 1.6** · "ไม่ลดราคาท้ายเกมเลย" แย่กว่าเล็กน้อยเมื่อคู่แข่งตัดราคาแรง → คง `ENDGAME` เดิม
  - ข้อจำกัด: sim ใช้ค่าสมมติ (คู่แข่งไม่ตอบสนองเรา, น้ำหนักเทศกาลเดา) ใช้ยืนยันว่า "ไม่แย่ลง" ไม่ใช่ "ดีที่สุด"
- ของที่เหลือหลัง R12 ไม่ควรเกิน ~25% ของทั้งหมด (ไม่นับล็อตที่ขายไม่ได้เลย) ถ้าเกินให้ดูก่อนว่าเหลือเป็นล็อตอะไร — ถ้าเป็นล็อตที่ผ่านสเปกแล้วแต่ราคาแพ้ ค่อยลด `START` ของประเภทนั้น −0.02 (ไม่ใช่เพิ่ม PACE)
- รอบสุดท้าย R15: ต้องเสนอของที่ขายได้ทั้งหมด (agent ทำอยู่แล้ว) พื้น 0.85 ไม่ลด

## ตัวชี้วัดระหว่างแข่ง (ดูทุก 2–3 รอบ ห้ามส่งมือ)
| ตัวชี้วัด | ปกติ | ถ้าเกิน |

| รอบที่ส่ง 0 ซอง ทั้งที่มีของขายได้ | 0 | ตรวจ log หาเหตุ (ROUND_CLOSED / spec / capacity) |
